# 独立面板方向复验（IRP）：可行性勘察与实验方案

目的：把 Jonikas 上的事后方向增益，在一个未参与开发的独立面板上，按冻结方案复现。

本文件是**投入前的可行性判定 + 方案**，不是预注册。真正的预注册在第 5 节，
只有第 3 节的数据门禁全部通过才写、才冻结、才跑。

---

## 0. 先决结论：按基因聚类算，现有增益的区间已经含零

在提任何新面板之前，必须先报一个刚测出来的数字，因为它改变了对现有证据的判断。

`PaD − D_only` 的方向 AUROC 增益 **+0.131195**，两种自助：

| 重抽单位 | 95% 区间 | SE |
|---|---|---|
| 无序对（此前所报） | [+0.0374, +0.2431] | 0.0525 |
| **基因聚类** | **[−0.0071, +0.2972]** | **0.0776** |

**按基因聚类，区间含零。** 聚类折减因子 **1.48**——30 个基因撑起 84 个对，
每个基因平均参与 5.6 个对，按对自助低估了将近一半的不确定性。

这正是你列的第四个必要条件里"在考虑共享基因依赖后仍有支持"那一条，而它在
**现有面板上就已经不满足**。两个后果：

1. 现有的 +0.131「区间不含零」只在按对自助下成立，论文里必须同时给出聚类区间。
2. 独立复验从"锦上添花"变成"必需"，同时门槛也被抬高了——见第 2 节。

## 1. 两条看起来现成的路，都已排除（有数据）

### 1.1 Jonikas 的 N-linked glycan 参照集：不独立

仓库里有 `N-linked-glycans_positive.txt`（9 条有向）和 `_negative.txt`（44 条），
共 53 条记录，从未进入 PaD 的拟合。但勘察结果：

```
glycan 基因 11 个，其中 10 个也在 KEGG 面板的 30 个基因里
glycan 的 53 对中，42 对直接出现在 KEGG 面板里（79%）
```

它基本是开发面板的子集，换了个通路标注。**不满足"未参与"**，而且 9 个正例
在第 2 节的任何一个功效档位下都不够。排除。

### 1.2 Costanzo 面板扩展：标注语义不对

`data/costanzo/INHERITED_SOURCES.json` 自己写明：

> "Masked significant total-expression-response orientation from the previous
> project; **not externally curated direct-edge truth**."

Costanzo 的 `target` 不是外部策展的通路方向，是前一个项目的表达响应方向。而 P
通道也源自表达数据（GSE42527）。拿它做"独立方向复验"会被审稿人以循环性直接
打掉，而且它量的根本不是同一个东西。排除。

（附带：该文件记录 `uncovered_pairs: 571`——标注集里还有 571 对没在 Costanzo
的 NxN 数据里匹配上。即使不管语义问题，这些对也没有测量。）

## 2. 功效需求：这是决定投不投的硬数字

以现有面板的**基因聚类** SE 0.0776 @ 21 正例为基准外推（SE ∝ 1/√n）。

**区间不含零所需**（临界，功效仅 50%）：

| 假设真实效应 | 所需正例数 |
|---|---|
| +0.131（完全复现，乐观） | 28 |
| +0.100 | 49 |
| +0.080 | 76 |
| +0.050 | 194 |

**80% 功效所需**（`SE = d / 2.8`，这才是该用的标准）：

| 假设真实效应 | 所需正例数 |
|---|---|
| +0.131（完全复现） | **58** |
| +0.100 | 100 |
| +0.080 | **155** |
| +0.050 | 395 |

开发面板上的效应量系统性偏高，独立面板上回归是常态。**规划值取 d = +0.08，
即需要约 155 个有向正例**；能接受的下限是 d = +0.131 的乐观假设，**60 个正例**。

对照 Jonikas 的 21 个：这是 **3 到 7 倍**的规模要求。任何低于 60 个有向正例的
候选面板，不必进入第 3 节。

## 3. 数据门禁（G1–G6），全部机械可检，全部通过才继续

每一条都给出可执行的判据，不留"看起来还行"的空间。

**G1 对级不相交。** 候选面板与 KEGG 168 条、glycan 53 条、Costanzo 657 对的
对级交集必须为 **0**。

**G2 基因重叠受控。** 与上述三个面板的基因并集的交集 ≤ **20%** 的候选面板基因数。
超过则必须把重叠基因整段剔除后重新过 G3。

**G3 规模。** 有外部策展方向的正例 ≥ **60**（绝对下限），目标 ≥ **155**。
负例按该面板自身的参照构造规则生成，不人为配比。

**G4 标注来源非循环。** 方向标注不得由单扰动或双扰动表型推导而来。可接受的来源：
策展的通路方向（KEGG / Reactome / MetaCyc 的酶促步骤顺序）、文献策展的上位关系
（SGD / BioGRID 的 directed genetic interaction）。**不可接受**：任何从生长适应度、
表达响应或双突变表型反推的方向。这一条要能指到具体的策展记录，不是声称。

**G5 三通道测量齐备。** 对每一个候选对：
- P 通道：两端基因在 P 编码器的输入表达矩阵中存在，且**不在** `frozen_P.json`
  记录的 564 个训练节点里（否则 P 通道被污染，必须剔除该对）
- D 通道：双扰动表型可得
- 上下文：第三伙伴集合非空（`|M_H| > 0`）
三项齐备的对数 ≥ G3 的阈值。

**G6 聚类功效。** 用该面板的真实基因-对二分图，做一次**纯结构**的功效模拟：
在 d = +0.08 的假设下，按基因聚类自助，检出力 ≥ **80%**。这一步不碰任何真实
测量值，只用连接结构，所以不消耗数据独立性。

门禁产物写 `irp_gate.json`，含每条的判据、实测值、通过与否。**任何一条不过就停，
不调门槛重试。**

## 4. 候选数据源与评估顺序

按"已有多少现成基础设施"排序，不按理想程度排序。

| 候选 | D 适配器 | 方向标注来源 | 主要风险 | 先查什么 |
|---|---|---|---|---|
| **Costanzo 2016 全库 + 外部通路方向** | **已冻结可用**（33 维） | KEGG/Reactome 酶促顺序 | G5 的 P 通道覆盖；G2 基因重叠 | 全库 475 端点之外的基因有多少能配上策展方向 |
| Jonikas DM 矩阵 + 外部通路方向 | 已冻结可用（23 维） | 同上 | DM 只有 444 基因，G3 很可能不过 | 444 基因内能凑出多少策展有向对 |
| Norman 2019 组合 Perturb-seq | **需新建** | 你已指出部分从单双表型推出 | **G4 大概率不过** | 方向标注的策展记录能不能指实 |
| 其他物种/其他双扰动筛 | 需新建 | 视来源 | P 编码器不可迁移 | 暂不评估 |

**第一顺位是 Costanzo 全库 + 外部通路方向**，唯一理由是它的 D 适配器已经冻结、
已经验证，不需要跨越 release 的重建边界。注意这与第 1.2 节不矛盾：那里排除的是
**继承的表达响应标注**，这里要换成**外部策展的通路方向**，是两套标注。

## 5. 如果门禁通过：冻结什么（草案，门禁通过后才定稿并算哈希）

**主指标（必须预先定，这是这次和上次最大的区别）：**

```
Delta_dir = AUROC(PaD, direction) - AUROC(best_single_channel, direction)
best_single_channel = max(P_only, D_only) 在该面板上，由同一套规则拟合后选出
```

方向 AUROC 是**主**指标，不是事后重评分。score AUROC 作为次要指标同报。

**对照（同一划分、同一规则、同一 35 候选容量）：** `P_only`、`D_only`、
`A_match`、`A_rbf`、`PaD`。全部沿用 `scc/families.py` 已有的实现。

**区间：** 主区间用**基因聚类自助**，按对自助作为次要口径同报。理由见第 0 节。

**预注册判据：**

```
IRP_REPLICATED      Delta_dir >= 0.05  且  基因聚类 95% 区间下界 > 0
IRP_ATTENUATED      Delta_dir >= 0.05  但  区间含零
IRP_NOT_REPLICATED  Delta_dir <  0.05
```

`0.05` 是实用幅度，不是统计阈值：方向 AUROC 提高 5 个点，才值得让一个拿到两种
扰动证据的人多做一次联合读取。

**退化预检**沿用 SCC 规格第 2 节（核秩、非常数分数、统计量支持、选择器可达性），
它是上一轮 CCCT 失效后加的那一道，不省。

## 6. 如果门禁不通过：退路，以及它值多少

诚实的预期是 **G3 和 G4 至少有一条会不过**。届时不再找替代面板，改为把现有
证据的边界写清楚，具体三件事：

1. **第 0 节的聚类区间进正文。** 把 +0.131 [−0.007, +0.297] 如实报，并说明按对
   自助为何低估。这是减分，但由作者说出来远好于被审稿人算出来。
2. **把方向增益降级为假设，配一个可执行的复验规格。** 本文件第 3 到 5 节原样作为
   附录发表：数据门禁、功效需求、预注册判据全都写死。审稿人问"怎么验证"时，
   答案是一份任何人拿到合格面板就能跑的规格，不是一段辩解。
3. **贡献表述改为两层不对称。** 理论层给出指定条件下联合读取的必要性（未受影响）；
   实证层只声称"在一块 21 正例的开发面板上观察到方向增益，按基因聚类不显著，
   复验规格已给出"。

这条退路拿不到 7 分，但它把当前这个 21 正例面板能承担的重量说准了。继续在
21 个正例上做更多分解，收益已经耗尽——第 0 节就是证据：换一种更正确的重抽单位，
现有结论就翻了。

## 7. 成本

| 阶段 | 内容 | 成本 |
|---|---|---|
| 阶段 A | G1–G6 门禁勘察，纯数据比对与结构模拟，不拟合 | 数小时，无模型运行 |
| 阶段 B | 门禁通过后：新面板的 P/D 适配（若沿用 Costanzo 适配器则仅数据装配） | 1–2 天 |
| 阶段 C | 冻结、算哈希、提交无结果的 commit | 1 小时 |
| 阶段 D | 五个学习器拟合 + 聚类自助 | 按面板规模，Costanzo 量级约数分钟 |

**阶段 A 是唯一需要现在决定的。** 它不消耗数据独立性（G6 只用连接结构），
不产生任何可被事后挑选的结果，而且它的输出直接决定后面三个阶段跑不跑。
