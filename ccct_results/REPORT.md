## 2. 第 15 节：接口消融

### 2.1 D+ 的构造，以及它为什么可信

release 交付的是准备好的 P/D 接口，不含历史上的 Jonikas D 适配器。所以
`ccct/dplus.py` 从存档的 `080930a_DM_data.mat` 重建第三伙伴上下文，并且
**不假设重建是对的**：它先从原始数组重算冻结的上下文坐标 18–22，要求逐位相等，
否则拒绝返回任何 D+ 块。

实测偏差：坐标 18、19、20、21、22 全部为 `0.0`。

这一条通过，是三个新描述子成为"同一批测量的描述子"而不是"保真度不明的再推导"
的唯一依据。

D+ = 26 坐标（11 奇 / 15 对称）。缩放常数 `d23 = 0.11867`、`d25 = 0.68420`，
按现有奇描述子的规则在无标签面板上算一次后冻结。164/168 条记录有上下文，
4 条缺失置零。伙伴并列数 **0**，所以 `c24` 的带符号秩形式与协议文本的
`2·frac(>) − 1` 在这块面板上是同一个数。

Δ₃ 把两个问题混在一起：补回的方向有没有用，以及多加三个坐标会不会伤害学习器。

作为尺度参照，冻结的 P 分数单独在同一块面板上是 AUROC 0.5364。

|---|---|---|---|---|
| 17 | 0.2949 | **0.0000** | 0.0564 | 0.0000 |

12,288 个独立测试实例上零错误。预注册的"`A_match(D+)` 接近零错误"成立。

### 2.5 结论

**R1 为假。** 补回被丢弃的方向没有让加法追平，反而把差距拉大到 0.296。
真实数据上的条件解释主张不需要撤回。

**原因是补回来的方向在真实面板上几乎不含信息**：两个残差类描述子在随机水平，
profile 差描述子弱反向。而在机制里，同样的恢复让加法控制降到零错误。
S4.2 说的方向 oracle 是**生成器的性质，不是测定的性质**。

这就是第 3 节"交换不变上下文接口"那句话的经验依据——从一个设计选择变成一个
实验结果。摘要相应改成 "a retained phenotype representation can carry no
directional information on its own"。

### 2.6 不该报的

**Δ₂ = 0.2809 不能当"协同仍在"。** 它是被 `A_match(D+)` 拖垮抬上去的，不是
PaD 涨上去的（PaD 只从 0.881 掉到 0.866）。三个接近随机的奇坐标占了线性 D
分量的 3/11，在 RBF 均方距离里方差约为原 23 个坐标的 1.9 倍，加法类没有办法
折价它们。它的选择计数说明了这一点：

| 学习器 | 权重选择计数（7 个候选） | 正则选择计数（5 个） |
|---|---|---|
| A_match(D) | [0, 6, 30, 0, 36, 1, 11] | [9, 64, 4, 0, 7] |
| A_match(D+) | [0, **36**, 10, 0, 32, 0, 6] | [3, 37, 13, 0, **31**] |

84 个外层组里，纯 D-odd 核的选择从 6 组涨到 36 组，最强正则从 7 组涨到 31 组，
这是学习器在吸收噪声的签名。PaD(D+) 只从 0.881 掉到 0.866，因为乘积核可以
压制一个无信息的 D 因子。

形式上预注册读法落在 **R4**（R1 假、R3 判据 `|Δ₃| ≤ 0.01` 不满足、R2 第一
子句满足但第二子句由 D+ 上的 CCCT 决定而未跑）。确立 R3 实质的逐坐标测量是
事后诊断，已如此标注。

| B4 | (1, 0, 0) | 645 (15.75%) | 644 (15.72%) | −1 | −1.082 | 0.9341 | 不拒绝 | 不拒绝 |

四个全部落在预注册位置。**预注册预测 3 命中。** B1 的 p = 0.001996 = 1/501
是 R = 500 的分辨率下限（500 次置换里 0 次达到观测值），恰好满足协议要求的
`p ≤ 0.002`。

**B5 是最有说服力的那个**，而且比预期更干净：D 对标签边际完全无信息，任何
边际筛查或相关分析都发现不了它，联合学习器却在 4096 个实例上多对 334 个，
而置换零分布**500 次全部精确为 0**（sd = 0）。破坏跨通道对应后，联合减加性的
增益归零——这是 Proposition CCCT-1 在数据上的样子。

### 4.1 一条必须写出来的结构性限定

B5 零方差的原因查清了，它不是 bug，但它限定了这四个对照能证明什么。

机制编码有两个结构事实：`odd` 块**全为零**，且 `xdr` 与 `xd` **精确相等**
（机制的 D 上下文摘要是交换对称的）。在有向任务里求解器做反对称化
`K ← (K − K_rev)/2`，于是：

- `A_match` 的第三分量 `(P+D)/2` 变成 `((P+D) − (P_rev+D))/4 = (P − P_rev)/4`
  ——**D 完全抵消**
- joint 的第三分量 `P·D` 变成 `(P·D − P_rev·D)/2 = D ⊙ (P − P_rev)/2`
  ——D 作为逐元素调制保留

所以**在机制面板上，加法控制在结构上退化为纯 P 模型**。论文自己的数据印证了
这一点：B1 的 formal 结果里 `A_match`、`A_rbf`、`full_P_RBF` 的错误数完全相同
（各 1298），B4 也完全相同（各 688）。

一次置换后的直接检验：joint 与 `A_match` 的方向预测符号一致率 4096/4096，
Pearson r = 0.9998，错误数相同。未置换时符号一致率 3654/4096，错误数 338 对 672。

**含义**：B1 与 B5 的拒绝验证的是"联合的乘性调制优于纯 P 基线"，不完全是
"联合优于加法融合"。这个退化在真实面板上**不发生**——Costanzo 与 Jonikas 的
`odd` 块非零且 `xdr ≠ xd`，`A_match` 在那里是真正的加法控制（Costanzo 613 对
P-only 597；Jonikas AUROC 0.8277 对 0.5364）。这条限定要写进论文，而不是
留给审稿人从 `result.json` 里发现。

## 6. 方法学发现

**一、D 置换会打开一条血缘泄漏通道，而且它会咬人。** 置换 D 改变了一条记录的
测量来源而没有改变它的名字，所以基于名字的端点排除不再约束训练集关于测试记录
D 来源的信息。协议 v1.2 的修法是把排除图建在"名字共享图与血缘共享图的并"上：
对外层测试对 `g`，训练对 `t` 必须同时满足 `genes(t) ∩ genes(g) = ∅` 与
`genes(σ(t)) ∩ genes(σ(g)) = ∅`，内层在池内重复同一规则。实测在 Jonikas 上
训练池从 66.3 对缩到 52.9 对（约 20%），在 Costanzo 的折内置换下是精确 no-op。
恒等置换下它逐组复现存档排除集，这是第 0 次复制的一部分。

**二、安慰剂匹配不是形式主义。** 更密的排除在零分布侧缩小训练池，对未触动的
观测统计量却不缩。Jonikas 试点实测：安慰剂匹配参照 **0.0587**，未触动观测值
**0.0534**。排除机制本身就把统计量抬高了约 0.005 AUROC。不做匹配会系统性低估
观测值相对零分布的位置。

**三、p 值是近似的，两个来源都写进了每一份输出记录。** 共享基因的记录不可交换；
零分布侧与安慰剂侧的排除图同分布但不同一。文档与论文文本里不使用 "exact"。

**四、机制面板上的加法控制退化为纯 P。** 见 4.1。

**五、pandas 会把字符串 `"null"` 读成缺失值。** 复制表的 `kind` 列存的是
`"null"` 与 `"placebo"`，默认读取器会静默丢掉全部零分布行。验证器改为关闭
默认 NA 识别、只把空字段当缺失。面板结果本身不受影响（那是内存里算的），
但任何下游读表的人都会踩到。
